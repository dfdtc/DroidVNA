# DroidVNA 0.5.0

> [中文版](../../release-notes/0.5.0.md)

UI rework (unified top-right menu + background watermark + collapsible controls + vertical acquisition rail in landscape), plus automatic settings and calibration memory.

## New

### UI

- **Unified top-right menu**: the measurement page no longer has a title bar. Sweep settings, trace settings, calibration, export, device, app settings, and hide-controls all live in the single top-right `⋮`. The trace chart can therefore use the full height.
- **Background watermark**: `DroidVNA` and its subtitle are drawn as a translucent watermark behind the trace chart, beneath the grid and traces. App settings → "Interface → Disable app watermark" removes the whole layer, leaving a solid background.
- **Collapsible controls**: the trace/mode/Y-axis control row and the acquisition card columns on large screens / on the left in landscape can be collapsed; there are three entry points: a menu item, the `⌃` at the end of the control row, and `⌃` on the acquisition card. Marker shortcuts remain available after collapsing.
- **Vertical acquisition rail in phone landscape**: when width ≥ 600 dp and the device is in landscape, a two-column layout puts the acquisition controls in a vertical column docked on the **left**, with the trace chart on the right, instead of a horizontal row at the bottom.

### Remembered settings

- Sweep parameters (start/stop frequency, points, IFBW, power, averaging, single/two-port, log sweep, auto continuous sweep), chart mode, trace parameters, Y-axis scaling, log frequency axis, watermark switch, marker positions, Δ markers, collapsed-control state, and UI language are all saved automatically and restored on the next launch.
- "Auto-start sweep after connect" can be turned off to require tapping "Start sweep" manually.
- Storage: `filesDir/settings.json`, written atomically via a temporary file plus rename, falling back to defaults if corrupted.

### Calibration memory

- SOL / THRU / E-Cal / `.cal` import results are saved as a snapshot (`filesDir/calibration.json`) immediately after every change, recording the device serial, source, coefficient set name, and update time.
- Loaded and applied automatically on the next launch; the measurement page shows "Loaded the previous calibration (…)" at the top.
- App settings → "Calibration memory" shows saved calibration details and offers **disable calibration** (keep the coefficients, show raw data only, re-enable at any time) or **forget the saved calibration**.
- Calibration is isolated per device serial: switching to another VNA never applies the old device's calibration, and switching back restores it.

## Fixes

- **Settings were not persisted**: the old implementation observed `MutableStateFlow` with `snapshotFlow`, but that is not Compose snapshot state, so the file was effectively written only once at startup. It now merges all state flows, debounces for 400 ms, compares content, and then writes.
- **Release signing**: `keystore.properties` may live in `android/`, the repository root, or `.github/`; a relative `storeFile` is resolved against the properties file's directory (supporting `../xxx.jks`). If the configuration exists but is invalid, the build fails immediately with the reason instead of silently producing an unsigned APK; the build log prints the keystore and alias actually used.
- v1 / v2 / v3 signatures are all enabled.

## Verification notes

- Toolchain: Gradle 8.14.4, AGP 8.13.2, Kotlin 2.4.21, compileSdk / targetSdk 36.
- 26 JVM unit tests pass (new JSON round-trips for settings/calibration snapshots, corrupted-file fallback, cross-device isolation).
- Hardware validation (Xiaomi Pad, Android 17):
  - tablet landscape two-column layout, top-right menu, watermark, collapsing and expanding controls;
  - phone landscape (`wm size 1080x2400` with density 440 to simulate 873×393 dp) confirmed the acquisition rail on the left and the chart on the right;
  - collapsed state, watermark switch, and sweep parameters were restored after a force-stop and restart;
  - Harogic B60 (FW 1.8.6) connection and continuous sweeping worked.
