# DroidVNA 0.7.4

> 中文: [docs/release-notes/0.7.4.md](../release-notes/0.7.4.md)

0.7.4 is a formal release (no beta suffix) that fixes the Smith-chart interaction and adds two practical tools.

1. The Smith chart no longer behaves like two layers while dragging: the constant-resistance circles now move with the constant-reactance arcs.
2. A new **Smith 3D sphere** for amplifier tuning: stability circles and source/load-pull contours that leave the unit circle (`|Γ| > 1`) have nowhere to go on a flat chart, but they render fine on the sphere.
3. Smith readouts gained a second number (imaginary part or angle), XdB search gained `+X dB` and a **valley** reference, and the dual-marker Δ gained a frequency difference — three values antenna and amplifier work keeps needing.

## Fixed

### Smith chart: the resistance circles did not follow a drag

The constant-resistance circles had their centre hard-coded to the middle of the control (ignoring `SmithView.focusIM`), while the reactance arcs and the trace used `gammaToOffset`. A vertical drag therefore moved only the trace and the arcs and left the resistance circles pinned, which looked like two layers.

Both circle families now derive their centre from the same `SmithView` through `gammaToOffset`, so the grid and the trace stay in step while zooming and panning. The reactance-circle centre was also corrected to the mathematically right Γ centre `(1, 1/x)` (it used to be `-1/x`, unnoticed because the graticule is symmetric about the real axis). Zoom/pan is still two-finger only; a single finger stays a crosshair readout.

### `SweepSettings` length chosen per device

0.7.2-beta sent 32 bytes to every device so the B60 would receive its `extTrigger` byte. That is now `Protocol.encodeSweepSettings(config, standby, legacy31 = true)`:

| Device | Packet length |
| --- | --- |
| LibreVNA hardware and unknown LibreVNA-compatible devices (default) | 31 bytes (upstream standard) |
| Harogic B60 (the driver passes `legacy31 = false`) | 32 bytes (with `extTrigger`) |

B60 behaviour is unchanged (still an explicit `extTrigger = 0`); other devices are no longer given an extra byte.

## Added

### Smith 3D sphere (`ChartMode.SMITH_3D`)

Reflection coefficients are projected onto the Riemann sphere: `|Γ| < 1` on the southern hemisphere, `|Γ| > 1` on the northern one, and `|Γ| = 1` is the equator.

- One-finger drag tumbles it (yaw/pitch), pinch to zoom, double-tap to reset; the reset button and the `×N` factor match the flat chart.
- The pitch is a **full turn**, not a limit — keep dragging past the pole and the passive hemisphere turns to face you.
- The wireframe and traces split into front/back halves by depth, the far side is translucent, and markers fade with depth.
- The sphere maths lives in `ui/chart/SmithSphereMath.kt`, free of Compose so it can be unit-tested.

### Smith readout: imaginary part or angle

Markers and the crosshair only printed `|Γ|`, which cannot tell two points of the same circle apart. They now append the **imaginary part** by default (`S11 |Γ| 0.184  Im +0.082`, signed, so you can see which side of the real axis the point is on), switchable to the **angle** (`∠26.6°`) in "Trace settings → Smith readout". Same point, two representations; display only.

### XdB / bandwidth search: `+X dB` and a valley reference

- A `±` button in front of the depth field picks the side: `−` below the reference (filter passband roll-off), `+` above it (antenna bandwidth).
- The shortcut chips lost their minus sign (1 / 3 / 6 / 10 / 20 dB); the direction button decides the sign.
- New **valley** reference: antenna bandwidth is measured upwards from the `|S11|` dip, and a peak reference can never produce a crossing when searching upwards. Flipping to `+` switches the reference to valley automatically, and back to peak when it returns to `−`.
- The result card gained a signed "offset" row (`+3.0 dB`), and the status messages use the signed form ("no +3.0 dB crossing found").

### Dual-marker Δ: frequency difference

With `Δ` on, a `Δf +768.750 MHz` line joins the per-trace amplitude deltas. Both markers are quoted at the sweep point they actually read at (the same rule as the marker cards), the sign shows which marker is higher, and the value is available while paused or before the first sweep.

## Verification

- **93 JVM unit tests pass.** This release adds: valley reference, `+X dB` both-side search, default direction still `−`, both Smith readout formats, the Riemann sphere (equator, hemispheres, poles, full-turn rotation), and a `smithReadout` settings round-trip.
- **Hardware** (Xiaomi Pad, Android 17), demo mode, item by item:
  - A Smith marker prints `|Γ| 0.184 Im +0.082`; switching to the angle makes the same marker read `∠26.6°`.
  - One-finger vertical drag past the pole turns the passive hemisphere to the front and the pole labels swap sides.
  - Flipping `−` to `+` moves the reference from peak to valley; a both-sides `+3 dB` search from the S11 dip (2.0875 GHz / −18.0 dB) finds edges at 2.0089 / 2.1828 GHz, bandwidth 173.88 MHz, centre 2.0958 GHz.
  - The dual-marker Δ reads `Δf +768.750 MHz`, matching the two marker cards (1.8188 / 2.5875 GHz).
- **Not yet verified**: DTF distance accuracy against a known cable, and the 31-byte standard packet on LibreVNA hardware.

## Upgrade notes

- `versionCode` goes from 12 to **13** (0.7.2-beta was 11; the intermediate 0.7.3-beta was only ever built internally and never published).
- The protocol is still **v14**, so no firmware update is needed; calibrated data keeps its format, so saved calibrations stay valid.
- Same signature, so it installs over the previous build.
