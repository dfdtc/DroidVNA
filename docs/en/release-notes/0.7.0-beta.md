# DroidVNA 0.7.0-beta

> [中文版](../../release-notes/0.7.0-beta.md)

Full **12-term two-port SOLT calibration** (issue [#2](https://github.com/dfdtc/DroidVNA/issues/2)), an isolation term that can be re-measured or replaced separately, and an explicit warning for uncalibrated bands.

> **This is a Beta release.** The 12-term SOLT E-Cal automatic flow has run end-to-end and applied successfully on real hardware (B60 + ECB-60), but **absolute accuracy has not been compared against the desktop app or a known DUT**, and **manual SOLT has not been run on hardware** yet (no mechanical standards). For metrology-grade work, keep using the desktop LibreVNA-GUI. See "Verification notes" at the end.

## New

### Full 12-term SOLT

Previous releases only did 1-port SOL (directivity, source match, reflection tracking) plus THRU normalization. THRU normalization cannot mathematically remove the transmission error caused by port mismatch: during THRU the DUT is replaced by a through whose S11/S22 are close to 0, so the mismatch term in the denominator is almost unobservable; with a real DUT, S21/S12 then has a systematic error that grows with port reflection.

The app now solves all 12 error terms and corrects every point with the multiport formula `S = B·A⁻¹`:

| Error term | Per port/direction |
| --- | --- |
| Directivity, Source Match, Reflection Tracking | Per port |
| Receiver Match, Transmission Tracking, Isolation | Per direction |

- **Manual SOLT**: the Calibration page has a new "Two-port SOLT" section with a prerequisites checklist, a THRU delay (ps) input, and a "Compute and apply full SOLT" button.
- **Fully automatic E-Cal**: a two-port kit runs Open/Short/Load on both ports → THRU, then solves the full model in one go.
- **`.cal` import**: when both ports' 1-port measurements and THRU are present, the full 12-term model is rebuilt directly and its Isolation measurement is read; with insufficient data it still falls back to 1-port SOL + THRU.
- **Demo mode** now uses a real 12-term error model, so SOLT can be exercised end-to-end without hardware.

### Isolation: optional and re-measurable

- The E-Cal isolation measurement is now an **optional checkbox, off by default**. Two-port electronic kits such as the ECB-60 have inherently poor isolation paths, and what they measure is often worse than two mechanical 50 Ω loads; it is off by default and can be enabled when needed.
- The isolation term can be **replaced separately** without redoing Open/Short/Load/THRU: terminate both ports with 50 Ω loads, capture once, and tap "Update isolation from this capture". Transmission tracking is derived from `(THRU S21 − isolation)`, so the snapshot stores both the measured and ideal THRU values and the replacement is an **exact recomputation**, not an approximation.

### Uncalibrated-band warning

When the sweep range exceeds the calibrated band, the "Calibration" card on the measurement page and the status card on the Calibration page both show "The sweep range covers an uncalibrated band" and list the calibrated band. Previously out-of-band points were skipped silently with no UI indication.

## Changes

- 1-port SOL error terms now use the same closed-form solution as LibreVNA-GUI's `computeOSL`, matching the desktop results.
- New dependency: Apache Commons Math 3.6.1; complex 2×2 solves and matrix inversion use `FieldLUDecomposition` instead of hand-written Gaussian elimination.
- Full SOLT takes precedence over 1-port SOL / THRU normalization; the two never double-correct.
- Calibration snapshot format is now version 3 (new `solt` section containing raw THRU data); old files still load.

## Fixes (found by independent review)

- **Manual SOLT now validates the sweep range of every capture**: THRU / port 2 / isolation used to be resampled onto port 1's grid, and interpolation **silently clamps out-of-band points to the endpoint value**, so error terms solved after changing sweep settings could be badly wrong with no visible symptom. `.cal` import got the same frequency-coverage check.
- **Standard models no longer produce NaN at 0 Hz** (`Through`, parametric `Open`, and `Load` with a shunt capacitor), so a start frequency of 0 Hz no longer shows up as "SOLT has no solution".
- **Truncated calibration snapshots can no longer crash with an out-of-bounds access** (coefficient array lengths are validated against the frequency grid).
- **Single-frequency calibration is rejected**; when **standards are too close** the app now reports no solution instead of producing absurd coefficients.
- Manual THRU normalization and `.cal` import now share the `measured / ideal` semantics.

## Verification notes

- Toolchain: Gradle 8.14.4, AGP 8.13.2, Kotlin 2.4.21, compileSdk / targetSdk 36.
- **All 48 JVM unit tests pass**. The correctness of the 12-term model is cross-checked in two independent ways:
  - the production forward model matches an **independent signal-flow derivation** point by point (1e-12);
  - corrected standards return to their ideal values (+1 / −1 / ideal through), a ground-truth check that does not reference the model.
- **Hardware validation** (Xiaomi Pad, Android 17 + Harogic B60 FW 1.8.6 + ECB-60 FW 0.3.2):
  - the 12-term SOLT E-Cal automatic flow solved and applied successfully at 401 points / 500 MHz–3 GHz;
    the measurement page showed `Acquiring CAL`, and the calibration card showed "Applied · 12-term SOLT · P1 SOL · P2 SOL", with no crashes;
  - both isolation checkbox settings ran (isolation measured / isolation not measured), and the default off behavior matched expectations;
  - after calibration, with the E-Cal set to NONE (equivalent to open), S11 ≈ 0 dB and S21 sat in the −80…−100 dB noise floor, which is physically plausible;
  - the "sweep range covers an uncalibrated band" warning appeared as expected.
- **Still unverified in this version**: amplitude/phase accuracy against the desktop app / a known DUT (needs mechanical standards and a reference filter), the complete manual SOLT flow (needs manual standard changes), and LibreVNA's own hardware.
