# DroidVNA 0.4.1

> [中文版](../../release-notes/0.4.1.md)

E-Cal two-port calibration fix; the app is renamed DroidVNA.

## Changes

- Renamed to **DroidVNA**, package name changed to `com.droidvna.app`, and the export directory to `Download/DroidVNA`.
- README / NOTICE / the in-app About panel now include a derivative-work notice: rewritten from the LibreVNA-GUI protocol and calibration logic (GPL-3.0), not affiliated with the LibreVNA project or Harogic.

## Fixes

- **E-Cal two-port calibration**: following LibreVNA-GUI's flow, **all E-Cal ports that will be used are first set to the same standard** (Open / Short / Load) before measuring any VNA port. Previously, switching port by port left the other port on NONE or the previous standard, so the measured Open/Short/Load did not match the coefficient definitions and SOL error terms looked like noise — especially visible on the Smith chart.
- **Release all E-Cal ports before THRU**, then establish `:PORT 1 THROUGH 2`, avoiding residual LOAD/OPEN states.
- After every `:PORT` switch, the actual state is verified with `:PORT?` and the relay gets 150 ms to settle; failures abort explicitly.
- The manual port mapping is fixed: **VNA P1 → E-Cal P1, VNA P2 → E-Cal P2**, no Auto; it is shown in the UI.
- **Coefficient-stream integrity check**: streaming `:COEFF:GET?` must return the same number of points as `:COEFF:NUM?`; truncated streams are no longer accepted as valid coefficients, avoiding spurs across the band from interpolation over too few points.
- A two-port sweep configuration is forced before two-port E-Cal calibration starts, ensuring the same standards are always measured in the same VNA mode.
