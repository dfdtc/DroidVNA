# DroidVNA 0.7.1-beta

> [中文版](../../release-notes/0.7.1-beta.md)

Adds a set of **marker analysis tools** next to the trace markers: bandwidth search, XdB search, and DTF (time domain / distance to fault). All three share the same markers and trace data and leave the existing sweep, calibration, and export paths unchanged.

> **This is a Beta release.** The analysis tools are validated in demo mode and JVM unit tests, but **DTF distance accuracy has not been compared against a real VNA, a known-length cable, or the desktop LibreVNA-GUI**. For metrology-grade work, keep using the desktop app.

## New

### Analysis entry point

A new **Analysis ▾** entry point sits next to the marker buttons (`+ Marker` / `Peak` / `Valley` / `Clear`), in:

- the collapsed top control row
- the marker bar below the chart
- the "Traces" card in the large-screen side column

It opens a second-level menu: **Bandwidth search / XdB search / DTF**. Each tool is configured and run from a bottom sheet. Markers created by an analysis are replaced by the next analysis; manual markers and custom cursors are untouched.

### Bandwidth search

- Uses a **peak** or a **custom cursor** (an existing marker) on the selected S-parameter trace as the 0 dB reference.
- Searches both sides for the **-X dB** level (default -3 dB).
- Crossings are linearly interpolated in the dB domain between adjacent samples instead of snapping to the nearest point.
- Adds the two edges as markers and reports the reference level, target level, lower/upper edges, bandwidth, and center frequency.
- A NaN gap left by a partially completed sweep ends the search in that direction; the tool never invents an edge across a hole.

### XdB search

- The general version of bandwidth search: search only the **left / right / both** sides of the reference.
- Bandwidth search reuses the both-sides XdB logic; a one-sided search only adds the edge it finds.
- The result explicitly reports "only the left/right edge was found" or "no crossing found".

### DTF (time domain / distance to fault)

- Applies a windowed IFFT to the **S11 / S22** complex reflection data. The IFFT uses the existing Apache Commons Math `FastFourierTransformer`; no hand-written FFT.
- Frequency data is resampled onto a uniform grid first, so log sweeps work too; then it is zero-padded, windowed, and transformed.
- Supports **rectangular / Hann / Hamming / Blackman** windows, IFFT zero-padding (1×/2×/4×/8×), velocity factor (default 0.66), cable-loss compensation, peak threshold, and a display distance limit.
- Distance conversion: `d = c · VF · t / 2`; range resolution: `c · VF / (2 · span)`.
- The result contains a distance-domain trace (relative amplitude, 0 dB = strongest reflection) and a distance-sorted fault table (distance, round-trip delay, relative amplitude), plus max distance, resolution, FFT size, window, and velocity factor.
- When the full range is shown, a few resolution cells at the far edge are trimmed: the IFFT is circular and a 0 m reflection wraps to the end of the record, which would otherwise be reported as a second fault at the maximum distance. The sheet notes that this region is excluded from the fault table.
- The computation uses the most recent **complete sweep**, so a partial sweep cannot silently change the frequency span.

## Implementation and tests

- New `model/analysis` module:
  - `XdbSearch.kt`: peak/cursor reference, left/right/both search, dB-domain interpolation, NaN-gap handling.
  - `Dtf.kt`: uniform resampling, windowing, zero-padded IFFT, distance conversion, peak detection, wrap guard.
- New UI:
  - `ui/components/AnalysisMenu.kt`: the second-level menu next to the markers.
  - `ui/sheets/AnalysisSheet.kt`: bandwidth / XdB / DTF bottom sheet.
  - `ui/chart/DtfChart.kt`: distance-domain chart.
- 15 new JVM unit tests: 7 for bandwidth/XdB search, 7 for DTF, and 1 for English UI translation. The suite now has **67 JVM unit tests, all passing**.

## Verification notes

- **All 67 JVM unit tests pass**. The analysis tests cover both/one-sided search, edge interpolation, unfinished sweeps, invalid X values, synthetic reflection distances, velocity-factor scaling, log-sweep resampling, peak threshold, display-distance truncation, and the 0 m wrap guard.
- **Demo-mode validation** (Xiaomi Pad, Android 17, demo DUT is a 1.75–2.65 GHz band-pass filter):
  - Bandwidth search found a reference peak at 2.3125 GHz and edges at 1.8157 / 2.5889 GHz, adding two edge markers; a second search replaced the previous analysis markers.
  - Left-only XdB search added only the left edge and reported "only the left edge was found".
  - DTF on the demo S11 produced about 15.7 m maximum distance, 4.0 cm resolution, and a 2048-point FFT; the distance trace, fault table, and 0 m wrap note all worked.
  - The analysis menu, sheets, and result text were fully translated in both Chinese and English.
- **Still unverified in this version**: DTF distance accuracy against a known-length cable / fault; bandwidth and XdB search on a real VNA; LibreVNA's own hardware.
