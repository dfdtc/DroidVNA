# DroidVNA 0.7.2-beta

> English: [docs/en/release-notes/0.7.2-beta.md](../en/release-notes/0.7.2-beta.md)

本版是**协议与校准可靠性修复**，没有新增功能。两条主线：

1. 发给 Harogic B60 的 `SweepSettings` 必须带第 32 字节 `extTrigger`，否则设备会沿用接收缓冲区里
   上一个包的残留值、进入“等触发”状态，看起来像卡死。
2. E-Cal 的采集超时不能再固定 8 秒，否则 15 Hz 这类低 IFBW 设置下，一遍完整扫描还没结束就会误报
   「端口 X 没有扫描数据」。

## 修复

### B60 通信协议：补上 `extTrigger` 扩展字节

VNB-60 的 `SweepSettings` 是 **32 字节**（上游 LibreVNA 是 31 字节），末字节 `extTrigger`
（`0` = 自由连续扫描，非 0 = 每个点等待 N 次外部触发）。固件把收到的包拷进一个**共享复用**的接收
缓冲区，并且只覆盖实际收到的字节，所以只发 31 字节时这个扩展字节会保留上一个包的值：

| 残留值 | 现象 |
| --- | --- |
| `0` | 正常连续扫描 |
| `1` | 只剩约 11 个点 |
| `0xFF` | 完全不出数，看起来像设备卡死 |

应用现在**固定发送完整 32 字节**，并把 `extTrigger` 显式写成 0；协议结构（`Protocol.SweepSettings`）
与单元测试一起锁定该布局，新增的 `packet type` 全表也避免类型号被误改。

### 移除“SA → VNA 模式复位”

旧版本在下发扫描配置前先发一帧 SA 配置再切回 VNA。这个规避只是**碰巧**把那段缓冲区覆盖成 0，所以
时灵时不灵（“成功、成功、失败”的随机循环，重发设置也不自愈），还给每次配置增加 0.8 秒以上等待。
现在配置被 ACK 但 6 秒内没有任何可用数据点时，改为**重发同一条配置**（最多 2 次），不再切换模式。

### E-Cal 采集超时按扫描时间自适应

- 超时 = 约 **2 个扫描周期**（下限 8 秒、上限 20 分钟），周期由点数与 IFBW 估算，并在有同网格实测
  扫描时间时以实测为准（B60 每点耗时不只取决于 IFBW）。
- 慢扫描**不再重复等第二遍**：只有首遍在 1 秒内就到达（可能是切换标准前的残留）时才等第二遍。
- 等待期间逐秒显示进度，例如「端口 1 OPEN · 已采集 286/401 点…」；THRU 与隔离测量同样。
- 手动 SOL 的「捕获」也使用同一超时逻辑。

### `DeviceStatus`（VD0）解码修正

`supply_current` 之前因长度判断写成 `>= 7` 而恒为 null（B60 的 VD0 只有 6 字节），且单位应为 mA；
同时补充 `FPGA_configured` / `extRefAvailable` 位，设备页新增 FPGA 状态灯与供电电流显示。

## 预留：外触发

外触发**尚未实现**：`SweepSettings.extTrigger` 字段、`SetTrigger`(28) / `ClearTrigger`(29) 包号以及
`syncMode = 3`（触发同步）都已在协议结构中预留并加了注释。Harogic 尚未定义非 0 值的语义
（实测 255 时完全无输出），因此应用始终发送 0。

## 验证

- **77 个 JVM 单元测试全部通过**（本版新增 10 个：32 字节 `SweepSettings` 布局与 `extTrigger` 预留、
  `packet type` 全表、`VD0` 状态解码、stage word 打包、触发预留保持关闭、非法帧长安全跳过、
  低速扫描超时放大并带上下限、慢扫描不重复等第二遍、实测扫描时间优先于估算）。
- **真机**（Xiaomi Pad，Android 17 + B60 FW 1.8.6 + ECB-60 FW 0.3.2）：
  - 连续扫描正常：401 点 / 3 kHz 实测约 3.0 遍/秒，日志显示 `SweepSettings(… extTrigger 0)`；
    15 Hz / 2001 点持续出点。
  - **E-Cal 低带宽**：401 点 / **15 Hz**（一遍约 30 秒，远超旧的 8 秒超时）完整 12 项 SOLT
    **一次通过**，约 7 分钟、7 次采集，进度逐秒可见；401 点 / 100 Hz 约 1.5 分钟通过。
    修复前同样的 15 Hz 设置必然在第一次采集就报「端口 X 没有扫描数据」。
- **尚未验证**：DTF 距离精度与真实电缆对照、手动 SOLT 上机、LibreVNA 官方硬件。

## 升级说明

- 协议仍是 **v14**，无需升级固件。
- 校准数据格式不变，已保存的校准可继续使用。
- 同一签名可覆盖安装；`versionCode` 由 10 升到 11。
