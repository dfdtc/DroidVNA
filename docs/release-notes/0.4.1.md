# DroidVNA 0.4.1

E-Cal 2 端口校准修复；应用更名为 DroidVNA。

## 变更

- 应用改名 **DroidVNA**，包名改为 `com.droidvna.app`；导出目录改为 `Download/DroidVNA`。
- README / NOTICE / 应用内「关于」增加衍生作品声明：基于 LibreVNA-GUI 协议与校准逻辑改写（GPL-3.0），
  与 LibreVNA 项目及 Harogic 无隶属关系。

## 修复

- **E-Cal 2 端口校准**：按 LibreVNA-GUI 的流程，先把**所有用到的 E-Cal 端口设成同一个标准**
  （Open / Short / Load）再测所有 VNA 端口。此前逐端口切换会让另一个端口停留在 NONE 或上一个
  标准，测到的 Open/Short/Load 与系数定义不一致，SOL 误差项会呈噪声状，Smith 图尤其明显。
- **THRU 前先释放所有 E-Cal 端口**，再建立 `:PORT 1 THROUGH 2`，避免残留 LOAD/OPEN 状态。
- 每次 `:PORT` 切换后用 `:PORT?` 校验实际状态，并给继电器 150 ms 稳定时间；失败会明确中止。
- 明确固定手动端口映射：**VNA P1 → E-Cal P1，VNA P2 → E-Cal P2**，不使用 Auto；界面中显示。
- **系数流完整性校验**：`:COEFF:GET?` 流式读取必须拿到与 `:COEFF:NUM?` 一致的点数；截断的流
  不再被当成有效系数，避免少量点插值导致整段频带出现杂散。
- 2 端口 E-Cal 校准开始前强制双端口扫描配置，保证同一组标准件始终在相同 VNA 模式下测量。

- 21 个 JVM 单元测试通过（SOL 数学已用真实 E-Cal `.cal` 标准件验证：校正后 Open/Short/Load 与系数定义误差 < 1e-15）。
- E-Cal 时序修复需要在 VNB-60 + ECB-60 实机上复测；如果仍有杂散，请附设备页日志中的
  `E-Cal coefficients:` 行。
